# 线段树进阶：懒标记（Lazy Tag）

> 前文：[《线段树入门：从「区间求和」讲起》](https://blog.kanako.top/blogs/xianduanshurumen-congqujianqiuhejiangqi)  
> 本文在「单点修改 + 区间求和」之上，讲清 **区间修改** 为什么需要懒标记，以及怎么写

---

## 1. 基础版做不到什么

基础线段树已经能：

- 单点改：`a[i] = val` → O(log n)
- 区间查：`sum(a[L..R])` → O(log n)

但如果题目变成：

> 把 `[L, R]` **整段每个数都加上 v**，然后再多次查询区间和

- 对 `[L, R]` 里每个下标调一次 `update` → **O(n log n)**，太慢  
- 真改到每个叶子 → 最坏还是 O(n)

需要一种操作：**区间加**，复杂度也是 O(log n) 
答案就是 **懒标记（lazy propagation）**

---

## 2. 懒标记是什么意思

> 修改可以先记在大区间节点上，**先不推到儿子**
> 等以后真的要访问儿子时，再把这笔账传下去

所以叫「懒」—— 能拖就拖，别没事往叶子跑

### 小例子

数组：`[1, 2, 3, 4]`，要对 `[0, 2]` 每个数 `+10`。

没有懒标记时，得改 3 个叶子，再更新一整串祖先

有懒标记时：

```text
找到能整段盖住的节点，例如 [0,1]、[2,2]
在这些节点上：
  - 立刻更新该节点自己的 sum（因为查询可能马上用到）
  - 记下 lazy += 10（表示：儿子们以后还要 +10，现在先欠着）
```

此时左右儿子的 `tree[]` 可能还是旧的——**没关系**，只要带着 `lazy`，语义是对的；真要往下走时再 `pushDown`

---

## 3. 每个节点多存一个 lazy

对「区间加 + 区间求和」，节点通常有：

| 字段 | 含义 |
|------|------|
| `sum` | 这段当前正确的区间和（已包含打在本节点上的加法） |
| `lazy` | 打在本节点、**尚未传给儿子**的「整段加算子」 |

约定：`lazy[p] = v` 表示「节点 p 所管区间里，每个元素还要再加 v，但这件事儿子还不知道」

---

## 4. 三个关键函数

建议把逻辑拆成：`apply` / `pushDown` / `pullUp`

### 4.1 `apply`：把一次「整段 +v」作用到当前节点

假设节点管的长度是 `len = nr - nl + 1`：

```text
sum[p]  += v * len      // 每个数 +v，和增加 v*len
lazy[p] += v            // 记住：儿子以后也要 +v
```

注意：`apply` 只改**当前节点**，不递归儿子

### 4.2 `pushDown`：下推懒标记

当即将访问左右儿子时（查询或修改都要对不齐往下走）：

```text
如果 lazy[p] != 0：
    apply(左儿子, lazy[p])
    apply(右儿子, lazy[p])
    lazy[p] = 0
```

推完后，本节点的「欠账」清零；儿子的 `sum` / `lazy` 被更新

### 4.3 `pullUp`：用儿子重算父亲

```text
sum[p] = sum[左] + sum[右]
```

区间修改在子树里改完后，要 `pullUp`，保证祖先的 `sum` 正确
（`lazy[p]` 本身不参与相加，它是标记不是值）

---

## 5. 区间加 `rangeAdd(L, R, v)`

和基础版查询很像，多了「整段命中就 apply 并返回」：

```text
在节点 p（管 [nl, nr]）上，给目标 [L, R] 每个位置 +v：

1. 无交集 → 什么都不做
2. 当前段完全被 [L, R] 包住 → apply(p, v)，直接返回   ← 懒的精髓
3. 部分相交 →
     先 pushDown(p)          // 往下走前必须下推
     递归左 / 右
     pullUp(p)               // 用儿子更新自己
```

复杂度：目标区间拆成 O(log n) 个整段节点，每段 O(1) 打标记 → **O(log n)**

---

## 6. 区间查 `query(L, R)`（带懒标记）

和基础版几乎一样，唯一区别：**往下走之前先 `pushDown`**

```text
1. 无交集 → 0
2. 完全被包住 → 返回 sum[p]     // 本节点 sum 已是最新的
3. 部分相交 → pushDown 后问左右
```

为什么命中整段时不用 pushDown？  
因为 `sum[p]` 在 `apply` 时已经按 `+v` 更新过了，对「只要这段的和」来说已经够用

---

## 7. 手算一遍

`a = [1, 2, 3, 4]`，建好后：

```text
           [0,3] sum=10
          /            \
    [0,1] sum=3      [2,3] sum=7
    /      \          /      \
  [0]=1  [1]=2    [2]=3    [3]=4
```

### 操作：`rangeAdd(0, 2, 10)`（下标 0..2 各 +10）

可能走法（示意）：

1. 根 `[0,3]` 没被完全包住 → `pushDown`（此时 lazy 为 0）→ 往下  
2. 左儿子 `[0,1]` 完全在目标里 → `apply`：`sum=3+20=23`，`lazy=10`，**不再往下**  
3. 右儿子 `[2,3]` 只有部分 → `pushDown` 后继续  
4. `[2,2]` 完全命中 → `apply`：`sum=13`，`lazy=10`  
5. `[3,3]` 不在目标里 → 不动  
6. 一路 `pullUp`：`[2,3].sum = 13+4 = 17`，根 `sum = 23+17 = 40`

此时叶子 `[0]`、`[1]` 的数组值**可能还显示旧的**，但带着父节点的 lazy，语义是「其实各该 +10」。  
若接着 `query(0,0)`，会在下推路径上把 +10 传到叶子，再返回 11。

### 再查：`query(0, 3)` → 直接 40（或下推后仍是 40）

## 8. Java 模板（区间加 + 区间求和）

```java
public class SegmentTreeLazySum {
    private final int n;
    private final long[] sum;
    private final long[] lazy;

    public SegmentTreeLazySum(int[] a) {
        n = a.length;
        sum = new long[n * 4];
        lazy = new long[n * 4];
        build(1, 0, n - 1, a);
    }

    private void build(int p, int nl, int nr, int[] a) {
        if (nl == nr) {
            sum[p] = a[nl];
            return;
        }
        int mid = (nl + nr) >>> 1;
        build(p * 2, nl, mid, a);
        build(p * 2 + 1, mid + 1, nr, a);
        pullUp(p);
    }

    /** 区间 [L, R] 每个元素 +v */
    public void rangeAdd(int L, int R, long v) {
        rangeAdd(1, 0, n - 1, L, R, v);
    }

    public long query(int L, int R) {
        return query(1, 0, n - 1, L, R);
    }

    private void rangeAdd(int p, int nl, int nr, int L, int R, long v) {
        if (nr < L || nl > R) return;
        if (L <= nl && nr <= R) {
            apply(p, nl, nr, v);
            return;
        }
        pushDown(p, nl, nr);
        int mid = (nl + nr) >>> 1;
        rangeAdd(p * 2, nl, mid, L, R, v);
        rangeAdd(p * 2 + 1, mid + 1, nr, L, R, v);
        pullUp(p);
    }

    private long query(int p, int nl, int nr, int L, int R) {
        if (nr < L || nl > R) return 0;
        if (L <= nl && nr <= R) return sum[p];
        pushDown(p, nl, nr);
        int mid = (nl + nr) >>> 1;
        return query(p * 2, nl, mid, L, R)
             + query(p * 2 + 1, mid + 1, nr, L, R);
    }

    private void apply(int p, int nl, int nr, long v) {
        int len = nr - nl + 1;
        sum[p] += v * len;
        lazy[p] += v;
    }

    private void pushDown(int p, int nl, int nr) {
        if (lazy[p] == 0 || nl == nr) return;
        int mid = (nl + nr) >>> 1;
        apply(p * 2, nl, mid, lazy[p]);
        apply(p * 2 + 1, mid + 1, nr, lazy[p]);
        lazy[p] = 0;
    }

    private void pullUp(int p) {
        sum[p] = sum[p * 2] + sum[p * 2 + 1];
    }
}
```

和基础版对比，就多了三处习惯：

1. 整段命中 → `apply` 后 return  
2. 往下走之前 → `pushDown`  
3. 子问题返回后 → `pullUp`

## 9. 常见坑

1. **忘了 pushDown**  
   部分相交时往下走，却不把 lazy 传给儿子 → 儿子还是旧值，答案错

2. **忘了 pullUp**  
   改完儿子不更新父亲 → 祖先的 sum 过期

3. **apply 公式写错**  
   区间和必须是 `sum += v * len`，不是 `sum += v`

4. **中点写成 `>>> 2`**  
   必须是对半切 `>>> 1`，否则树极深，轻松把 `4n` 数组撑爆越界

5. **多种懒标记混用**  
   「区间加」和「区间赋值」的 lazy 语义不同，不能随手一个 `lazy` 糊弄；赋值通常要覆盖加法标记。本文只讨论区间加

---

## 10. 和基础版的关系（一张表）

| | 基础线段树 | 带懒标记 |
|--|------------|----------|
| 典型修改 | 单点改 | 区间加（或赋值） |
| 修改复杂度 | O(log n) | O(log n) |
| 额外字段 | 无 | `lazy` |
| 往下走之前 | 不用 | 必须 `pushDown` |
| 整段命中修改 | 继续递归到叶子 | `apply` 后直接返回 |

骨架还是那棵二分区间树；懒标记只是让「大段修改」可以停在中层节点。

---

## 11. 小结

1. **能整段改就整段记在节点上，别急着下叶子**  
2. **自己的 sum 要立刻算对；欠儿子的账放进 lazy**  
3. **真要碰儿子之前，先 pushDown；改完儿子，再 pullUp**

练熟「区间加 + 区间求和」之后，同一套骨架可以换成：

- 维护区间 max / min（加一个常数时 max 也加）  
- 同时维护 `sum` 与 `sumSq`（`d → d+v` 时平方和用代数展开更新）  
- 再去做更难的数据结构题
