# 1477. 找两个和为 Target 的不重叠子数组：我怎么把最优解滑丢了

做 [LeetCode 1477](https://leetcode.cn/problems/find-two-non-overlapping-sub-arrays-each-with-target-sum/) 的时候，第一反应很顺：数组全是正数，滑动窗口找「和等于 target」的子数组，把长度丢进列表，最后取最短的两段相加。

测了几个样例都过了，直到撞上这组：

```text
arr = [2, 1, 3, 3, 2, 3, 1], target = 6
```

正确答案是 **5**（`[3,3]` 长度 2 + `[2,3,1]` 长度 3），我算出来却是 **6**。

下面把踩坑和改法记一下。

---

## 一开始的写法

思路就三步：

1. 前缀和 + 双指针，找出所有和为 `target` 的窗口；
2. 命中后把长度塞进 `lengthList`，然后 **`start = end`**，从窗口右端之后继续搜（保证不重叠）；
3. 列表排序，取最短两个相加。

伪代码大概是这样：

```java
while (end <= arr.length) {
    int winSum = sum(start, end - 1);
    if (winSum < target) end++;
    else if (winSum > target) start++;
    else {
        lengthList.add(end - start);
        start = end;          // ← 问题就在这
        end = start + 1;
    }
}
// 排序，返回最小的两个长度之和
```

看起来很合理：既然要两段不重叠，找到一段就跳过它，再找下一段，最后挑最短的两段——既不重叠，长度又小。

可惜，**「贪心跳过」收集到的候选，不一定包含最优解需要的那一段。**

---

## 错在哪：把 `[3,3]` 滑丢了

还是上面那组数据，窗口从左往右扫：

| 步骤 | 窗口 | 和 | 动作 |
|------|------|----|------|
| 1 | `[2,1,3]`（下标 0..2） | 6 | 记录长度 3，**`start` 跳到 3** |
| 2 | 从下标 3 再开搜 | … | 最终找到 `[2,3,1]`，长度 3 |

得到长度列表 `[3, 3]`，答案 `6`。

中间其实还有一段：

```text
下标:  0  1  2  3  4  5  6
值:    2  1  3  3  2  3  1
              └─[3,3]─┘     ← 长度 2，和也是 6
```

`[3,3]` 的左端落在第一段里面。我命中 `[2,1,3]` 之后一跳，这段就彻底没机会进列表了。

而全局最优偏偏要用它：

```text
[3,3] + [2,3,1] = 2 + 3 = 5
```

所以不是滑动窗口本身错了，是 **「找到就跳过，再从长度列表里取 Top2」** 这个组合策略错了：  
你丢掉的可能正是更短、且能和后面拼出更优答案的那一段。

---

## 差点二次踩坑：只改 `start++` 也不够

有人会想：那命中后别跳那么狠，改成 `start++`，把所有合法窗口都收集起来，再取最短两个？

对这道题的样例，碰巧可能蒙对；但对下面这个就不行了：

```text
arr = [2, 2, 2], target = 4
```

合法窗口只有：

- `[2,2]`（下标 0..1）
- `[2,2]`（下标 1..2）

两段都长度 2，**互相重叠**。题目要求不重叠，应返回 **-1**。  
若只存长度再取 Top2，会得到 `2+2=4`，依旧是错的。

结论：

> 不仅要找到「和为 target 的子数组」，还要在组合时**显式保证不重叠**。只比较长度不够。

---

## 改法：左边最短 + 当前窗口

仍然用滑动窗口，但换个记账方式：

- 扫到右端点 `end` 时，若存在窗口 `[start, end]` 和为 `target`，长度为 `len`；
- 维护 `minLeft[i]`：在下标 `0..i` 范围内，出现过的合法子数组的**最短长度**；
- 当前这段要跟左边拼，左边必须完全在 `start` 之前，用 `minLeft[start - 1] + len` 更新答案。

直观理解：

```text
|←—— 左边已结算的最短合法段 ——→| [start ........ end]
         minLeft[start-1]              当前窗口 len
```

对应代码核心：

```java
int[] minLeft = new int[n];
Arrays.fill(minLeft, Integer.MAX_VALUE);
int ans = Integer.MAX_VALUE, best = Integer.MAX_VALUE;
int start = 0, sum = 0;

for (int end = 0; end < n; end++) {
    sum += arr[end];
    while (sum > target) sum -= arr[start++];
    if (sum == target) {
        int len = end - start + 1;
        if (start > 0 && minLeft[start - 1] != Integer.MAX_VALUE) {
            ans = Math.min(ans, minLeft[start - 1] + len);
        }
        best = Math.min(best, len);
    }
    minLeft[end] = best;  // 扫过 end 为止，见过的最短合法长度
}
return ans == Integer.MAX_VALUE ? -1 : ans;
```

再跑一遍 `[2,1,3,3,2,3,1]`：

| 命中窗口 | `minLeft[start-1]` | 能否更新答案 |
|----------|-------------------|-------------|
| `[2,1,3]` | 无 | — |
| `[3,3]` | 左边没有不重叠的合法段 | — |
| `[2,3,1]` | `[3,3]` → 2 | **2+3=5** ✓ |

`[2,2,2]`、`target=4` 时，两段始终重叠，`minLeft[start-1]` 一直用不上有效值，最终返回 `-1`，也正确。

时间 O(n)，空间 O(n)，正数数组下滑动窗口依然成立。

---

## 小结

| | 错误思路 | 正确思路 |
|--|----------|----------|
| 收集方式 | 命中后 `start = end` 跳过 | 继续滑，不丢短窗口 |
| 组合方式 | 所有长度里取最短两个 | 当前段 + **严格在左边**的最短段 |
| 重叠 | 靠「跳过」间接保证，却漏解 | 用下标边界显式保证 |

一句话：

> **滑动窗口负责「找到合法段」；最优的两段组合，要靠「左边最短前缀」来拼，不能靠贪心跳过再取 Top2。**

写完这题最大的收获：贪心收集候选集时，先问一句——**我丢掉的那些，会不会恰好是更优解的一部分？**
